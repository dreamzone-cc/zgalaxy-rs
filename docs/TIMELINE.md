## المحور الأول — محرك الشبكة (zgalaxy-rs daemon)

### المرحلة التأسيسية — بناء النواة المتوافقة
1. **العميل والمتحكم المتوافقان مع ZeroTier** — ثنائية واحدة تعمل بالاسم
   `zerotier-one` (توزيع argv0: ‏zerotier-cli/zerotier-idtool)، REST محلي على 9993
   (X-ZT1-Auth + /status و/network و/peer) ومتحكم مدمج بواجهة ztnet الكاملة
   (/controller/*). *الأساس الذي جعل الاستبدال ممكناً.*
2. **الهوية والكريبتو** — ed25519، اشتقاق عنوان 10-hex، `idtool` أصلي بـvalidate
   وrc=2 لسوء الاستخدام.
3. **Data Plane الحقيقي (المرحلة 2)** — TAP حقيقي L2 مع MTU ‏1186، ‏MAC حتمي
   SHA-256 لكل (node,nwid)، ‏join بلا اختراع عناوين، وتطبيق العنوان/المسارات على
   المضيف عند وصول NetworkConfigResponse.

### محور النقل — من UDP الخام إلى QUIC
4. **أ1 — توكن العضوية الموقّع** — إصدار/تخزين/تقديم/فرض داخل مسار QUIC؛
   membershipToken ظاهر في /network، وسحب التفويض يسري خلال TTL.
5. **أ3 — ربط هوية QUIC** — تحدي/إثبات إلزامي (NodeChallenge → AnnounceProof
   موقّع، مرتبط بعنوان العقدة) قبل منح الحضور والتسجيل؛ مصفوفة سلبية كاملة.
6. **ب2 — مبدّل L2** — تعلّم MAC→endpoint + evict ‏5m + توجيه انتقائي (unicast
   للمالك، flood للبث/المجهول).
7. **ب3 — الحضور والقياس** — NodeAnnounce→PeerManager + touch_member_last_seen +
   RTT prober ‏10s يغذي /peer بزمن مقاس.
8. **ب4 — التعافي** — idle-timeout ‏15s + replace-on-dial + إخلاء MAC عند الفقد +
   نبضة تكيفية 500ms/3s + انتظار AnnounceAccepted. **النتيجة المقاسة: join→ping
   ‏2.1s بعد restart** (الهدف ≤5s).
9. **ج1+ج2 (المحرك ZGALAXY)** — unified planet بهويات جذور حقيقية عبر
   /api/v1/identity/public + التقاط تلقائي عند addNode.

### محور الجاهزية الإنتاجية
10. **ب1 — عقدتان E2E** — بنية اختبار قابلة للتكرار على 161 (zg-a/zg-b +
    b1_test.sh): join→تخويل→OK→IP تلقائي→ping عبر TAP↔QUIC.
11. **ب5/ب6 — روتين النشر** — deploy_161.sh ‏(deploy/verify/rollback) ببنية musl
    ونسخ احتياطية ثنائية+volume.
12. **ROLLOUT R0→R2** — نشر ثنائيتين تعزيزيتين (bcde6efe ثم 1a22b4a0)
    VERIFY-PASS، ‏B1/B4-PASS، نقع ‏31 دقيقة (8959/8959، فقد 0%، ‏mdev ‏0.10ms)،
    **D1 محسومة**: عضو حي واحد من ثلاثة → R3 محجوب حتى ترقية الأعضاء أو وضع
    مزدوج QUIC+UDP.

### إصلاحات جوهرية اكتشفها الاستخدام الفعلي
13. **نقطة إعدادات الشبكة (مرحلة 4 جزئياً)** — أعلام allow* حقيقية في Network
    + POST /network/{id} جزئي + **فرض فعلي**: allowManaged يحكم تطبيق المضيف
    وallowDefault يحجب 0.0.0.0/0. (فخ camelCase مع allowDNS صطاده اختبار).
14. **إصلاح ztnet "Could not create network"** — السبب الجذري: ‏
    `allowManagementFrom` داخل `settings` في local.conf الكلاسيكي لم يكن يُستخلص
    (كما primaryPort) → ztnet مرفوض كلياً منذ بوابة أ. الإصلاح في config.rs +
    3 اختبارات + تحقق حي من داخل حاوية ztnet.
15. **إصلاح CLI الصامت** — جسم JSON غير الصالح كان يُستبدل بـ{} بصمت →
    parse_rest_body بخطأ عالي الصوت + 3 اختبارات انحدار.
16. **تسوية rustc/E0514** — فخ argv0 في أدوات rustup يخلط نسخ المترجم؛ الحل
    الموثق: `RUSTUP_TOOLCHAIN=stable` صراحةً.

## المحور الثاني — التكامل مع ztnet (استبدال كامل لzerotier)

17. **حزمة `deploy/ztnet/`** — التثبيت الجديد والترحيل:
    - Dockerfile: ‏zgalaxy musl يُثبَّت **كـzerotier-one نفسه** (روابط argv0 +
      healthcheck توافقي)
    - docker-compose: postgres + zgalaxy + **صورة ztnet الرسمية بلا أي تعديل**
      عبر ZT_ADDR والمجلد المشترك
    - **setup.sh**: ‏fresh / migrate (مع حفظ الهوية والتحقق قبل/بعد) /
      update-binary / verify / rollback — كتابة local.conf عبر temp+docker cp
      (الاقتباس المتداخل كان يفسدها بصمت)
18. **`docs/ZTNET-INTEGRATION.md`** — المعمارية، عقد التوافق الأربعة، فخ
    allowManagementFrom الموثق بتاريخه، التثبيت/الترحيل/الاستكشاف.
19. **التحقق**: ‏verify على إنتاج 161 = VERIFY-PASS (بما فيه مسار ztnet→المتحكم)؛
    منظومة معزولة محلية من الصفر بصورة ztnet الرسمية 0.8.3 = ztnet→zgalaxy
    HTTP 200.

### الموجة 1 — الهيكل والوظائف الأساسية
20. **P0 skeleton → إعادة هيكلة §11.2** — الطبقات:
    `app/` (state + commands) · `network/client.rs` (REST وحيد) ·
    `platform/` (linux) · `storage/config.rs` — main.rs غرّة ربط فقط.
21. **نموذج الحالة المركزي §10** — OverallState بتحقيق مركزي بالأولوية (مشكلة←

    Waiting for approval…) + kind() دلالي — مشتق واحد تستهلكه الشارة والتراي

22. **التراي الحقيقي §6.1/§9** — SystemTrayIcon بقائمة ديناميكية (حالة/فتح/

### الموجة 2 — التصميم الاحترافي (Design Tokens)

    **عرض نوافذ موحّد 460px** وأطوال حسب المحتوى — أي ضبط مستقبلي بسطر واحد.
27. **مكونات التصميم** — StatusPill (شارة حالة ملونة: لون+إيموجي+نص §15) ·

28. **بنية النافذة الرئيسية** — ترويسة (شارة+Retry+Join) ← خط فاصل ← قسم

29. **إصلاح هندسة العرض** — أبعاد أول فتح كانت مكسورة (قِيست فعلياً: ‏90x579)؛

    تحقق نهائي بالقياس: كل النوافذ 460×الصحيح من أول مرة.

### الموجة 3 — الهوية البصرية والسلوك الحي
30. **الشعار الرسمي** — ZGalaxy.svg المصدر الأوحد: تحويل rsvg لمربع 256px،
    استبدال كل الأيقونات (تراي/نوافذ/حول/فراغ).
31. **أيقونة الحالة الحية** — التراي يتلون: **ذهبي عند الاتصال، أحمر عند عدمه**
    (الذهبي هو الشعار الأساسي في كل مكان)؛ التنفيذ عبر global ‏AppTrayState
    (SystemTrayIcon.icon خاصية in بلا واصلة) مع فك ترميز داخل خيط الواجهة
    (Image غير Send) عند تغيّر الحالة فقط.
32. **تكامل سطح المكتب** — مدخل قائمة تطبيقات النظام (فئة Utility عمداً — ليست Internet) + تشغيل تلقائي نظامي (/etc/xdg/autostart) عند التنصيب عبر install.sh، مع عدم ازدواج الإطلاق مع تفضيل المستخدم (نفس معرّف الملف = override).
33. **السلوك النهائي للنوافذ §17** — إغلاق الرئيسية مع تراي = إخفاء للتراي
    (on_close_requested)؛ بدون تراي = إنهاء؛ تراي اختياري (Option) بلا عملية
    شبحية؛ startup في الخلفية بلا تراي يعرض النافذة إلزامياً.
34. **إصلاح "Join لا يظهر"** — تشخيص تجريبي (الزر يعمل وshow()=Ok): الجذر =
    show() لا تفعل شيئاً للنافذة المرئية + زر الانضمام كان مقصوراً على حالة
    الفراغ. الحل: present() بإعادة تقديم + زر دائم في الترويسة.
