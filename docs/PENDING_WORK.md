## zgalaxy-rs — فحص معمّق + تهيئة GTP (2026-10-10، فرع feat/gtp-readiness)
المرجع: **docs/GTP-INTEGRATION.md**. ‏91 اختباراً أخضر (كانت 69)، clippy صفر، واختبار
دخان حي لعمليتين حقيقيتين (متحكم + عميل عبر REST مثل ztnet).

### أعطال مُصلحة (كلها بأدلة واختبارات انحدار)
- [x] **MTU 2800 مع QUIC = إسقاط كل إطار > ~1200 بايت** (انحدار commit a8d633a):
      الإطار الأكبر من حد الـdatagram يُرسل الآن على uni-stream؛ الحد الفعلي من
      `max_datagram_size()` لا من ثابت. متوافق مع الأقران القدامى (يتوقف لكل اتصال
      لا يمنح stream credit بدل دفع 50ms لكل إطار).
- [x] **تذبذب اتصالات QUIC على مقبس `[::]`**: النظير IPv4 يظهر `::ffff:a.b.c.d` بينما
      يُطلب `a.b.c.d` → كل دورة sync تفوّت الجلسة وتستبدلها ("replacing stale
      connection"). ‏`canonical_endpoint` لكل المفاتيح. الدليل الحي: join→أول رد
      **6.1s → 0.09s**، جلسة واحدة لكل طرف بدل الاستبدال المتكرر.
- [x] **إخلاء MAC عند فقد النظير لم يعمل أبداً**: الاتصال كان يُحذف من الجدول قبل
      إرسال Disconnected، فيُعامل كل فقد حقيقي كـ"replaced". ‏`active_generation()`.
- [x] **throttle الحضور كان يُعاد إنشاؤه مع كل حدث** (HashMap داخل الحلقة) →
      قفل+كتابة متحكم لكل إطار وارد.
- [x] **احتمال deadlock** في flood: قفل قراءة peers محتجز عبر send_frame→connect
      (tokio RwLock عادل: كاتب منتظر = تجمد).
- [x] **قفل dial عام** كان يسلسل كل الاتصالات (هدف ميت يحجز الجميع حتى 15s) →
      قفل لكل remote. و`send_frame` لم يعد يطلب اتصالاً (لا تجمد data plane).
- [x] **دورة sync تنتظر أبطأ هدف**: جذر resolver ميت كان يمدّ كل دورة إلى 5s →
      مهمة مستقلة لكل هدف (واحدة in-flight). الدليل الحي: تخويل→OK ‏**5.5s → 0.43s**.
- [x] **سباق إثبات الهوية**: رد المتحكم قد يصل قبل إثباته عند العميل فيُرفض →
      الطلب ينتظر اكتمال الإثبات في الاتجاهين (`await_mutual`).
- [x] **أمان**: إطارات من جلسة QUIC غير مُثبتة الهوية كانت تُحقن في TAP → تُسقط.
- [x] **أمان**: أي نظير مُثبت كان يستطيع دفع NetworkConfigResponse لأي شبكة (عناوين
      + default route) → يُقبل فقط من متحكم الشبكة (أول 10 hex من nwid).
- [x] **أمان**: جسر UDP غير المشفر يعمل بجانب QUIC كان يحقن إطارات في TAP ويقلب حالة
      التخويل بحزمة مزوّرة → `BridgeMode::ControllerOnly` بجانب QUIC (تسجيل join
      لـztnet فقط)؛ `settings.udpBridge=false` يعطّله كلياً.
- [x] **حبس دائم للعضو**: توكن منتهٍ (جهاز نائم > ساعة) كان يُرفض فيُحرم العضو المخوّل
      للأبد (الرد وحده يحمل توكناً جديداً) → سجل العضو هو المرجع، التوكن يُجدد.
- [x] **رد متأخر يعيد إحياء شبكة فصلها المستخدم** (قراءة-تعديل-كتابة غير ذرية) →
      `NetworkManager::apply_controller_config` ذري، يتجاهل الشبكات المفصولة، ويكتب
      للقرص عند التغيير فقط (كان كل 3s لكل شبكة).
- [x] **المتحكم يحذف عناوين يدوية**: إطفاء v4AssignMode.zt حذف كل IPv4، وإطفاء
      6plane/rfc4193 حذف كل `fc*`/`fd*` → الأعلام تحكم التعيين التلقائي فقط (دلالة
      ZeroTier)؛ العناوين المشتقة وحدها تتبع أعلامها.
- [x] إزالة عنوان من الواجهة بـ`/24` ثابت بينما أُضيف بـprefix المسار (‏/16 مثلاً) →
      الإزالة كانت تفشل بصمت. ‏`interface_sync` يزيل بنفس الـCIDR، وأوامر `ip` على
      blocking pool لا على خيوط async، وMTU المتحكم محدود بقدرة النقل.
- [x] مسارات IPv6 (`"v6/port"`) كانت تُحلَّل خطأً في nat/main/transport → `parse_path_address`.
- [x] قائمة مسارات النظير تنمو بلا حد مع كل NAT rebinding → سقف 8.
- [x] `allowManagementFrom` لا يطابق عميلاً IPv4 بصيغة `::ffff:` → `to_canonical`.
- [x] NAT keepalive في وضع QUIC كان يطلب اتصالات تسلسلية بلا مهلة لكل مسار قديم →
      متوازٍ بمهلة 3s ويتخطى الجلسات الحية (الـprober يغطيها).
- [x] local.conf تالف كان يُتجاهل بصمت (← loopback فقط) → تحذير صريح.
- [x] `-d` كان يكسر بناء Windows (`CommandExt` بلا cfg) + تحذير watchdog مضلل في
      الوضع headless + clippy في CI.
